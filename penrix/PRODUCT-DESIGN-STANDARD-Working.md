# Penrix Private｜产品设计标准、最终体验与逐站对标（Working）
> 日期：2026-11-04  
> 适用范围：Penrix/firefox → Android Fenix 私人站点超级 App。  
> 此文档是**产品设计与验收契约**，不是当前已实现功能清单。作者已有官方 Firefox；本应用用于**少数指定站点的极致定制**。Chrome 扩展为加分项。运行设备 Redmi K20 Pro / Android 9。

## 0. 顶层判断与边界

**最终产品不是另一个通用 Firefox、不是网址收藏夹、不是 PWA 启动器。它是一款包含数个独立网站 App 模块的私人 App。**

一站一模块：从产品入口、信息结构、常用任务、动作布局、状态记忆到异常回退均围绕该站设计。Firefox / GeckoView 是网页运行底座，不是用户主要看到的产品。

最终成功的检验方式：
1. **进入一个模块后，看到的是该站的专属操作界面**，不是进入通用浏览器网站首页；
2. **一条高频任务能连续完成**，而不必反复寻找网页按钮；
3. **切走再回来继续原处**：不丢列表筛选、内容对象、滚动/阅读位置（能保留哪个取决于当前页面与适配层）；
4. **原站内容、登录、发帖、播放器真实工作**，遇到网站变动、验证码、登录等可切回原网页；
5. **一个站点的体验问题不拖垮其他站点**；
6. 每个网站要比用官方 Firefox 打开同站**实质性减少步骤或提高阅读/观看质量**，否则该模块还没有完成。

目前 `PenrixSiteHome.kt` 仍以 `Card → 进入模块 → 打开站点首页/继续浏览 URL` 为主要 UI，`PenrixNovelRoutes.kt` 只是 URL 分类，**并没有完整站点 App 体验**。这一点是下一轮实施必须跨越的距离。

## 1. 对标对象：对标交互结果，不克隆产品

| Penrix 对象 | 产品/界面对标 | 应学到的具体体验 | 明确不照搬 |
|---|---|---|---|
| **总体容器** | 微信小程序式“一个 App → 多个独立模块”交互隐喻；**Android Material 3** 作控件与导航基线 | 全局模块总入口、近期继续、模块切换、各模块独立导航栈；符合单手操作 | 不用微信生态/服务端体系，不做小程序平台 |
| **69书吧 / TWKAN / UU看书** | **阅读3（Legado）的使用体验**，并参考通用电子书阅读器的沉浸页 | 书架、搜书、作品详情、目录、源切换、字体/行距/背景、连续章节与阅读进度 | 不复制阅读3代码或整体设置复杂度；不做“上千书源平台”。注：`gedoor/legado` 官方仓库截至查询已清空软件源文件，**只作 UX 参考** |
| **WNACG / 其他指定漫画站** | **Mihon**（https://github.com/mihonapp/mihon） | 封面网格、作品详情、章节/图集列表、连续看图、预加载、缩放、阅读位置与返回 | 不复制它的“海量插件源”复杂度，不替网站另建内容平台 |
| **SIS001 / Cool18 等论坛** | **RedReader**（https://github.com/QuantumBadger/RedReader） | 分类/帖子列表/帖子正文、快速返回原列表与位置、收藏、长楼层阅读 | 不复制 Reddit 专属投票/账号协议；回复/登录应直接接原站 |
| **Iwara / 其他指定视频站** | **NewPipe**（https://github.com/TeamNewPipe/NewPipe），只参考移动播放与列表 UX | 作品卡片、视频详情、观看进度、全屏、返回列表、尽量少的播放器干扰 | 不假定 NewPipe 提取器支持这些网站；不重造解码器或绕过站点权限 |
| **统一基础 UI** | Android 官方 Compose / Material 3 | 文本层级、触摸区域、返回、反馈、深浅色及无障碍 | 不让几个站点全变成一张同款 Material 卡片列表 |

## 2. 宏观信息架构（产品可被感知的层次）

```text
【Penrix Private 总入口】
    |
    +-- 【继续上次】真实内容对象（如某书的第 X 章、某论坛帖子、某图集）
    +-- 【我的站点】只显示已选模块，优先固定常用站点
    +-- 【收藏/记录】跨站统一对象入口（不是 Firefox Bookmark）
    +-- 【设置】站点配置、去广告、阅读与缓存
    |
    +------点击 69书吧 ---->【69 专属首页】
    |                           ├── 搜索/站点分类/常用列表
    |                           ├── 作品详情 -> 目录 -> 原生阅读器
    |                           ├── 当前站内进度/最近访问
    |                           └── 原网页/登录/异常回退
    |
    +------点击 TWKAN ----->【TWKAN 专属首页】
    |                           └── 同类型但按 TWKAN 实际页面和玩法定制
    |
    +------点击 WNACG ----->【漫画专属模块】
    |                           └── 发现 -> 详情 -> 连续图集阅读
    |
    +------点击某论坛 ----->【论坛专属模块】
    |                           └── 版块 -> 帖子列表 -> 楼层/回复
    |
    +------点击某视频 ----->【视频专属模块】
                                └── 列表 -> 详情 -> 播放 -> 恢复
```

**全局导航与站内导航不能双重占用屏幕**：总入口是切换模块的主控制台；进入模块后，站点自己的顶部栏/场景操作取代全局多列网址网格。不要在一屏同时叠加 Firefox 地址栏 + App 主底栏 + 站点底栏 + 网页原导航。站内有固定“回全部站点/换站点”和“完整网页”入口。

Android 官方推荐同层 3–5 个目的地时使用底部导航；**本站数量不固定，因此主入口优先用站点网格/最近继续，站内是否需要底栏则由该站实际功能决定**。不要机械地每站塞 5 个底部按钮。

## 3. 最终效果的三个页面样板（文本线框；非已实现画面）

### A. App 总首页

```text
┌─────────────────────────────────────┐
│  Penrix Private                ⚙    │
│                                     │
│  继续上次                            │
│  [书名 · 69书吧 · 第128章   继续→]   │
│                                     │
│  我的站点                            │
│  [69书吧] [TWKAN] [UU看书]           │
│  [WNACG ] [论坛 ] [Iwara ]           │
│                                     │
│  最近访问 / 收藏                      │
│  [最近帖子 ...]                      │
│  [最近图集 ...]                      │
└─────────────────────────────────────┘
```

重点：**“继续上次”必须指向具体作品/章节/帖子/图集，不能永远只是保存的网页 URL；URL 只是实现载体。** 占位样本不是作者实际书架数据。

### B. 小说站专属首页 → 作品 → 阅读

```text
【69书吧】              [换站] [原网页]
[搜索本网站的小说……]
[分类] [榜单] [最近]（只有本站真实可用时才出现）
[上次阅读：作品 A · 第128章 继续]

点作品 A
  → 封面 / 书名 / 作者 / 简介
  → [继续阅读] [加入书架] [目录] [原站]
  → 目录按卷/分段懒加载（上千章节不整体渲染）

点继续阅读
  → 原生沉浸阅读（默认无网址栏、无网站浮层/无广告）
  → 轻点呼出 [目录 / 字体 / 上一章 / 下一章 / 进度]
  → 返回作品或此前列表（滚动位置保留）
```

真正的小说 App 不是一张“打开站点首页”的卡，而是**从挑书到读书、再到下次续读完整闭环**。

### C. 论坛 / 漫画 / 视频最低限度结构

```text
论坛：站点页 → 版块 → 帖子列表（保留筛选/滚动）
                → 帖子正文/楼层 → 原站回复 → 原位置返回

漫画：站点页 → 封面列表 → 作品/章节 → 连续图集阅读
                → 图片缩放/翻页/预载 → 回原作品

视频：站点页 → 视频列表 → 作品详情 → 原生/原站播放器
                → 全屏/返回/进度 → 回原列表
```

论坛的发帖、复杂验证和网站账号逻辑保留 GeckoView 原网页；漫画优先原生看图；视频**先保留真实播放器**，只有确认效果更优才替换。不同站点允许采用不同程度的“原生化”。

## 4. 设计规范：按能力与体验划分，不靠空泛审美形容词

### 4.1 统一交互与视觉基线

| 维度 | 设计约束 | 反例 |
|---|---|---|
| **清楚的层级** | 总首页→网站→该站对象→内容；每一屏有明确主标题与关键动作 | 每屏都是几张含糊卡片，只能“打开网站” |
| **站点身份** | 顶栏显示所在网站/当前对象，站点可用自己的图标与强调色；全局文字与按钮规则统一 | 全站统一空白卡片，不知道在哪个模块 |
| **主动作** | 当前页最高频动作在单手可触区域可见；次要功能收进菜单 | 下一章、查看目录隐藏在网页页脚 |
| **触摸尺寸** | 目标触摸区域至少 **48×48dp**（Android 无障碍推荐） | 小字链接密集，误点 |
| **布局** | 初始水平边距 16dp、间距采用 4/8dp 的节奏；以 K20 纵向窄屏为设计基准 | 手机首屏过多无意义标题/留白 |
| **字体与主题** | 主体尊重 Android 字体缩放；阅读单独调字号/行距；默认跟随系统明暗，提供 AMOLED 黑色选项 | 字体固定、夜间闪白、正文挤压 |
| **返回与切换** | 返回上个明确上下文；切站保留原站栈；异常能进完整网页 | 退出帖子重新回论坛首页 |
| **过程反馈** | 骨架加载/真实进度/空状态/失败与重试；不伪造内容 | 白屏、不停转圈、打开失败后没法回退 |
| **广告** | uBlock Origin 网络过滤 + 站点 DOM 级细化清理，正文/按钮/播放器不能误删；允许站点级暂时停用 | 删除所有同类元素，破坏真实功能 |
| **私人数据** | 模块进度、收藏本地持久化，Cookie 由 GeckoView 管；正常/隐私会话隔离 | 偷存 Cookie 到书架库；关闭后丢进度 |

### 4.2 操作与性能目标（产品目标，尚未经真机测量）

- **响应**：点击主要按钮应立即出现可见反馈；对于纯本地模块切换，目标 500ms 内呈现首屏交互状态，网络加载另行显示。
- **返回**：同一进程中的模块切换不应主动摧毁原站标签；即便 Activity 重建，也应保留可恢复的状态。
- **长列表**：章节上千、帖子上百、图集上百张，必须使用虚拟列表/分段与按需图片加载；不能整个 DOM 或全部图片同时塞入 Compose。
- **内容正确率优先于速度**：任何章节正文/目录若无法稳定识别，保留原网页入口；不制造空白“原生页面”。
- **页面可用性**：站点登录、搜索、图集、回帖、视频全屏、原网页按钮不得被净化误伤。
- 以上指标需要用**Redmi K20 Pro / Android 9 实机**记录，目标不等于已达标。

## 5. 设计与工程之间的中间契约

当前只有 `SiteModuleRegistry` 和最后 URL，不足以支持“像 App”。应逐步构建：

```text
SiteDefinition（站点身份、主页、域名与功能开关）
    ↓
SitePageDetector（当前页面属于列表/作品/目录/正文/帖子/图集/播放）
    ↓
SiteContentAdapter（真实页面内容与动作结构；可拆 DOM/URL/API，但不得凭空造数据）
    ↓
SiteUiState（每站独立：当前列表、筛选、对象ID、章节/页码、滚动位置、tab ID）
    ↓
SiteView（根据站点实际高频任务选择原生列表/原生阅读/原网页混合）
    ├─ 识别成功 → 专属 App 操作
    ├─ 认证/验证码 → Firefox 当前会话网页 → 返回恢复
    ├─ 页面改版 → 记录错误/原网页 → 更新适配器
    └─ 离开本站 → 保留该站状态；切换其他模块
```

其中两条边必须同时成立：
- **原生 App 控制行为**（操作、状态、连续阅读）；
- **真实网站决定数据/权限**（不能因为设计稿需要，就假造不存在的栏目或绕开账号要求）。

现有保存 URL 的 `PenrixSiteHistory` 只是一维历史，不能等同于多页面模块状态。扩展时建议以 `SiteSessionSnapshot(siteId, tabId, route, contentKey, listKey, scrollOffset, readerPosition, updatedAt)` 为实际语义，用稳定 ID 联系原站与 Penrix 书架。字段不是强制一次建齐，按首个小说站真实需要补齐。

## 6. 一站一份设计约束：避免通用 UI 吞掉网站差异

每个正式纳入的站点必须有一份 `penrix/sites/<id>.md`，至少包含：

| 必填项 | 必须填写具体事实 |
|---|---|
| 站点是什么 | 实际域名、登录方式、页面布局/主要内容对象、真实页面样本 |
| 为什么要定制 | 在原 Firefox 中最常遇到的 3 个具体摩擦（广告、重复导航、跨章、返回丢位置等） |
| 对标什么 | 参照哪个 App 的哪个**具体页面/动作**，不是一句“像 XX 一样漂亮” |
| 目标截图线框 | 首页/列表/内容详情/阅读或播放/失败或登录，至少 4 类真实页面状态 |
| 一条完整用户任务 | 例如：从模块首页搜书→作品→目录→第 N 章→下一章→退出→再进入 |
| 数据/状态 | SitePageDetector 如何识别，什么应缓存/保存，怎么恢复 |
| 是否仍需要原网页 | 哪些动作保留网站原生交互、哪些进入原生 UI |
| 测试证据 | 对照同一页面原 Firefox 与 Penrix：步骤数、可见干扰、返回与恢复、实机问题 |

`SiteRegistry` 里有这个站的 ID **不意味着该站的深度定制完成**。

## 7. 验收门槛与推进顺序

```text
Firefox 原生工程可构建、独立安装 [F0]
                   ↓
Penrix App 总首页可真实运行 [F0.5]
                   ↓
选择一个具体小说站（建议 69书吧/TWKAN 中有证据最完整者）
                   ↓
该站首页/目录/内容的真实页面模型
                   ↓
像 App 一样的界面 + 站点实际操作闭环
                   ↓
对照 Firefox 原站逐项验证
       ├── 任务没缩短？→ 返回交互设计
       ├── 不能复位？  → 返回 SiteUiState
       ├── 内容不全？  → 返回 DOM/Source 适配
       ├── 登录失败？  → 返回 Gecko 原网页路径
       └── 真机成立   → 冻结该站 UX 基线，继续另一站
```

**第一个真正完成的模块**应证明：完整真实搜索/进入作品→目录→正文/下一章→书架/进度→切离再回，主要动作比原 Firefox 更连贯；没有把网站广告、浏览器控件和重复式导航全部搬进新 UI。

只完成图标、卡片、域名白名单、URL 分类、uBlock 自动安装都**不足以称为“站点 App 模块完成”**。
